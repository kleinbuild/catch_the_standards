0006 Model relatedness as typed, directed edges plus concept tags, in SQLite

Status: proposed, 2026-10-13

Store relationships between standards as rows in an `edges` table (from, to, type, weight, source, reviewed), and describe what each standard involves through tags against a hand-built `concepts` list. Use SQLite.

Prerequisite relationships have a direction and similarity does not. L.3.1e comes before L.5.1b; the reverse is false. Text similarity scores are symmetric and rise with shared wording, so they cannot say which standard comes first, and they can link standards that only share vocabulary.

Storing every pair is wasteful. ELA alone has 568 standards, about 322,000 pairs, nearly all unrelated. Only existing links get a row.

Concept tags give interpretable dimensions. Each standard or sub-item is tagged with concepts (e.g. "verb tense") and a role (introduces, develops, expects mastery). Relatedness between standards can then be computed from shared concepts and explained in plain terms to an IEP team.

Edge sources, from most to least trusted:
1. Structural: same strand and number in consecutive grades (0005). Generated by the loader.
2. CDE text: science and computer science standards cite ELA standards in their text. K-2-ETS1-2 lists "SL.2.5" under "California Common Core State Standards Connections"; K-2.AP.10 cites "(CA CCSS for ELA/Literacy W.K.3, W.1.3, W.2.3)". Parse with regex.
3. Embedding suggestions from a local model, stored with `reviewed=0`.
4. Owner review, which sets `reviewed=1` or rejects.

SQLite is enough at this size. Recursive queries can walk prerequisite chains, and `networkx` can read the tables for analysis or diagrams. A graph database is not needed.

Not decided: the concept list itself, whether to seed it from an existing learning map (Dynamic Learning Maps, Core Content Connectors, Achieve the Core coherence map; none checked yet), and the exact edge types.
